# Handoff: アキナエルAI 顧客マイページ（新規UI/UX設計）

## 概要
アキナエルAIの顧客向け「マイページ」を、既存画面の改修ではなく新規に設計したUI/UXプロトタイプです。店主・事業者がAIに相談 → 相談内容を確認・承認 → 制作 → 成果物確認、という一連の体験を、内部システム用語（Workflow / Task / Request / Artifact / Human Gate 等）を一切見せずに完了できることを目的としています。

## このファイルについて
`顧客マイページ.dc.html` はデザインリファレンス（HTMLプロトタイプ）です。見た目・状態遷移・モーションの意図を示すために作られたものであり、そのまま本番コードとして流用するものではありません。実装は既存のReact + TypeScript + Vite環境に合わせて再構築してください。

## Fidelity
高忠実度（hifi）。色・タイポグラフィ・余白・角丸・シャドウは下記トークンの具体値を基準とし、主要画面をピクセル精度で再現する。ただし、チャットのAI応答や進行の自動タイマーは挙動意図を示すモックであり、本番では実AI構造化処理・制作進行イベントへ置き換える。

## 1. ホーム
目的: 今の状態と次にやることを一瞬で理解させる。1画面1CTA。

Next Actionカードは状態に応じて内容を変え、状態変化時に `cardIn` 0.5sでフェード＋translateY(10px→0)。簡易ステップは「相談→内容確認→制作→完成」。

| 状態キー | 見出し | 説明文 | CTA |
|---|---|---|---|
| not_started | まずはAIに相談してみましょう | 普段の言葉で、やりたいことを話すだけで大丈夫です。 | AIに相談する |
| chatting | AIと相談中です | 続きから相談を進めましょう。 | 相談を続ける |
| summary_ready | 相談内容がまとまりました | 内容と料金をご確認ください。 | 内容を確認する |
| approved | 制作を準備しています | 担当チームが制作の準備を進めています。 | なし |
| in_production | ただいま制作中です | 完成まで今しばらくお待ちください。 | なし |
| revision | 修正内容を確認しています | 内容を確認して、担当チームが対応中です。 | なし |
| completed | 制作物が完成しました | 出来上がった内容をご確認ください。 | プレビューを見る |
| final_check | 最終確認をお願いします | 内容をご確認のうえ、完了操作をお願いします。 | 成果物を確認する |

## 2. AIに相談
- 初回はAI挨拶＋提案チップ: Webサイト / SNS / チラシ / 集客 / 何から始めればよいか。
- ユーザー吹き出しは右寄せ、accent-700背景＋白文字。AIは左寄せ、neutral-100背景。
- 入力中は3点ドットの `dotBounce`。
- 相談内容が十分まとまると「相談内容がまとまりました」カードを表示し、相談内容画面へ誘導。
- 制作物からの「修正をお願いする」で開いた場合は対象成果物名を文脈として保持。
- Enter送信、Shift+Enter改行。

## 3. 相談内容
正式依頼前に「何を作るか／いくらか」を確認・承認させる。承認するまでは正式発注にしない。

表示内容:
- 相談タイトル
- AI要約
- 制作内容
- 含まれる作業
- 納品物
- 予定金額（税込）
- 補足事項

主要CTAは「この内容でお願いする」。押下直後に `checkPop` で明確な視覚フィードバックを出す。本番では承認APIを呼び、モックの自動進行は使わない。副CTAは「AIに修正を相談する」。

## 4. 制作物
- カードグリッド。Webサイト種別はPC/スマホ2種のプレビュー、その他は1枠。
- 状態タグ: 制作中 / 確認できます / 修正対応中 / 完成。
- 「修正をお願いする」で成果物名を文脈としてAI相談へ。
- Webサイト種別は「プレビューを開く」を表示し、実 `preview_url` を開く。
- 制作物が無い場合は控えめな空状態。

## 5. プラン・お支払い
Stripe Customer Portal接続を前提にした最小構成。
- 現在プラン、契約状態、月額、次回支払日。
- 「プランを変更する」は変更前後の料金を明示するダイアログ。
- 支払い方法はカード末尾4桁等、安全に取得できる範囲のみ。
- 請求履歴は日付・金額・状態。
- 解約は最下部の控えめなリンク＋確認ダイアログ。

## 6. 設定

- 店舗名/会社名
- メールアドレス
- パスワード変更（リセットメール）
- メール通知ON/OFF
- 保存フィードバック
- ログアウト

## モーション規則
- `cardIn`: fade + translateY(10px→0), 0.5s ease
- `dotBounce`: 3点を0/0.15/0.3s遅延
- `checkPop`: scale 0→1.2→1, 0.5s
- 新規/更新成果物カードは `cardIn`
- 完了トーストは3〜3.5秒
- モーションは状態変化と次アクションを伝えるためにのみ使う

## 状態管理
- `screen`: home | chat | summary | works | plan | settings
- `appState`: not_started | chatting | summary_ready | approved | in_production | revision | completed | final_check
- `messages`
- `chatContext`
- `works`
- `summaryUnread` / `worksUnread`
- `currentPlanId` / `selectedPlanId`

本番では `appState` を実際のAI構造化完了・承認API・制作進行・成果物確定イベントへ紐づける。

## 実装上の核心
- UIに Workflow / Task / Request / Artifact / Human Gate 等の内部語を露出しない。
- prototypeのsetTimeoutやモックデータをproductionへ持ち込まない。
- 実DB/API/Workflowをadapter層で顧客向け状態へ変換する。
- 成果物プレビューは実生成物・実 `preview_url` へ接続する。
- 顧客承認は正規の承認記録・Workflowへ反映する。
